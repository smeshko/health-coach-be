## Goal

Define the four **ingest** SQLAlchemy models (`records`, `workouts`, `workout_statistics`,
`activity_summary`) under `app/database/models/` and an Alembic migration that creates them on `app.db`
with the exact UNIQUE/index/FK constraints from DB.md §1 — schema only, no data.

## Scope

- **`app/database/models/records.py`** — `Records` model mirroring `baseline.db` plus `uuid`/`origin`:
  `id` INTEGER PK; `uuid` TEXT **UNIQUE, nullable** (NULL for seeded rows); `type` TEXT NOT NULL; `unit`
  TEXT; `value` REAL; `value_text` TEXT (category enums — sleep stage / stand state); `source_name` /
  `source_version` / `device` TEXT; `creation_date` TEXT; `start_date` TEXT NOT NULL; `end_date` TEXT;
  `origin` TEXT NOT NULL. Constraints: `UNIQUE(uuid)`, index `(type, start_date)`, index `(start_date)`
  (DB.md §1; epic R4/R5).
- **`app/database/models/workouts.py`** — `Workouts` model: `id` PK; `uuid` TEXT **UNIQUE** (nullable —
  NULL for seed); `activity_type` TEXT NOT NULL; `duration` REAL + `duration_unit` TEXT; `total_distance`
  REAL + `total_distance_unit` TEXT; `total_energy_burned` REAL + `total_energy_burned_unit` TEXT;
  `effort_score` REAL **nullable** (RPE 1–10 from `WorkoutEffortScore`); `physical_effort` REAL
  **nullable** (METs proxy); `source_name` / `source_version` / `device` / `creation_date` TEXT;
  `start_date` TEXT NOT NULL; `end_date` TEXT; `origin` TEXT NOT NULL. Constraint: `UNIQUE(uuid)`
  (DB.md §1; epic R4/R5).
- **`app/database/models/workout_statistics.py`** — `WorkoutStatistics` model: `id` PK; `workout_id`
  INTEGER **NOT NULL**, FK → `workouts(id)`; `type` TEXT NOT NULL; `start_date` / `end_date` TEXT; `sum`
  / `average` / `minimum` / `maximum` REAL; `unit` TEXT. Index `(workout_id, type)` (DB.md §1; epic R5).
- **`app/database/models/activity_summary.py`** — `ActivitySummary` model: `date` TEXT **PK, NOT NULL**
  (upsert by date — Europe/Sofia date; explicit `nullable=False` since a TEXT PK is NULL-tolerant in
  SQLite); `active_energy_burned` + `active_energy_burned_goal` REAL; `apple_exercise_time`
  + `apple_exercise_time_goal` REAL; `apple_stand_hours` + `apple_stand_hours_goal` **INTEGER**;
  `apple_move_time` + `apple_move_time_goal` REAL (DB.md §1).
- **`app/database/models/__init__.py`** — import/re-export all four models so `Base.metadata` sees them
  for autogenerate and any `import app.database.models` registers them on the shared `metadata`.
- **One Alembic migration** under `alembic/versions/` (autogenerated then hand-checked) — `down_revision`
  = E2·P1's initial revision; `upgrade()` creates the four tables with the exact constraints/indexes;
  `downgrade()` drops them in FK-safe order (`workout_statistics` before `workouts`).
- **Tests** (`tests/database/`) — Alembic `upgrade head`→`downgrade base`→`upgrade head` round-trips with
  these tables; the four tables + their columns/types exist after `upgrade`; duplicate `uuid` on
  `records` / `workouts` is rejected; the `workout_statistics.workout_id → workouts(id)` FK and the listed
  indexes exist; `activity_summary.date` is the PK.

## Out of Scope

- **Writing / upserting data** — `INSERT … ON CONFLICT(uuid) DO NOTHING`, the `activity_summary`
  date-upsert, the type-whitelist filter, and `daily_metrics` recompute are all E5 (`/sync`). This phase
  defines **only schema + migration** and asserts constraints; it does not exercise the write path
  (epic §3 note, §7; DB.md §6).
- **Seeding from `baseline.db`** (E4) and the `date_components`→`date` rename mechanics — E4 copies the
  trailing ~90 days with `origin='seed'`; this phase just provides the target schema (DB.md §1, §6).
- **The other five tables** — `daily_metrics`, `checkins`, `strength_tests`, `plans`, `suggestions` are
  E2·P3 (epic §3).
- **Engine / WAL / Alembic scaffolding / period-key & timestamp helpers** — delivered in E2·P1; this
  phase reuses `get_engine`/`set_sqlite_pragmas`/`Base`/`metadata` and the configured `alembic/` without
  re-creating them.
- **Finalizing the exact HealthKit type-whitelist** (`HK…Identifier` set incl. `HKQuantityTypeIdentifierDietary*`)
  — an open item resolved before the first **sync** (E5), not a schema constraint here (DB.md §7).
- **Dropped stack** — Postgres/pgvector, Celery, Redis, Supabase, streaming, RAG/`vecs`
  (ARCHITECTURE §1 stack note).

## Research Summary

The four ingest tables structurally **mirror `baseline.db`** so the 90-day seed (E4) is a near-straight
copy, with exactly two additions: a unique `uuid` (idempotency key for `/sync`) and an `origin` flag
(`'seed'` from `baseline.db` | `'sync'` live) — DB.md §1, epic R4. `records.uuid` is **UNIQUE but
nullable** because seeded rows carry no HealthKit UUID (`NULL`); SQLite/ANSI treat multiple `NULL`s as
distinct, so the unique constraint admits all seeded rows while still rejecting duplicate live UUIDs
(DB.md §1). The required uniqueness/indexing is exact (epic R5): `records` → `UNIQUE(uuid)` + `(type,
start_date)` + `(start_date)`; `workouts` → `UNIQUE(uuid)`; `workout_statistics` → index `(workout_id,
type)` with a FK to `workouts(id)`; `activity_summary` → `date` is the PK (the upsert key). All timestamps
are ISO-8601 **TEXT** columns (offset preserved as emitted — E2·P1's helpers); period keys go through
Europe/Sofia (E2·P1). `effort_score` (RPE 1–10) and `physical_effort` (METs) are workout columns that do
**not** exist in `baseline.db` — they are purpose-built here (ARCHITECTURE §3). This phase defines schema
only; the write path (idempotent upsert, whitelist, recompute) is E5 (DB.md §6; epic §7). The migration's
`downgrade()` must drop `workout_statistics` before `workouts` because of the FK, and E2·P1's connect
listener already enables `PRAGMA foreign_keys=ON` so the FK is actually enforced at runtime.

## Decisions

- **Models live in `app/database/models/` as one module per table, re-exported from `models/__init__.py`**
  — keeps each table reviewable in isolation and gives Alembic a single import (`import app.database.models`)
  that registers all four on the shared `Base.metadata` for autogenerate (epic E2·P2; mirrors the E2·P1
  base/metadata target).
- **`records.uuid` and `workouts.uuid` are `UNIQUE` but `nullable`** — DB.md §1 marks `records.uuid` NULL
  for seeded rows; `workouts` seeds the same way. SQLite treats each `NULL` as distinct under a UNIQUE
  index, so all seeded rows (NULL uuid) coexist while a duplicate **non-NULL** uuid is rejected — which is
  exactly the idempotency contract (DB.md §1; epic R4/R5).
- **`activity_summary.date` is the table PK (no surrogate `id`) and is declared explicitly `NOT NULL`** —
  DB.md §1 says `date` is the PK and the table is upserted by date; a TEXT primary key is the natural
  upsert/cache key (one Apple-rings row per Europe/Sofia day), matching the `daily_metrics`/`checkins`
  date-PK pattern in later phases (DB.md §1–§3). In SQLite a non-`WITHOUT ROWID` TEXT PRIMARY KEY does
  **not** imply NOT NULL — multiple NULL rows would be admitted and silently break the date upsert — so
  the column is declared `primary_key=True, nullable=False` and a test asserts `PRAGMA
  table_info(activity_summary).notnull == 1` for `date` plus a NULL-date-insert rejection (round-1 #1).
- **All timestamp columns are `TEXT`, not SQLite `DATETIME`** — the contract (E2·P1, epic R2, DB.md §0)
  stores ISO-8601 TEXT carrying the per-sample offset HealthKit emits; a `DATETIME`/`DateTime` type would
  invite normalization. Storing as `String`/`Text` keeps the emitted offset verbatim and sorts correctly
  (DB.md §0).
- **`workout_id` FK declared with `ForeignKey("workouts.id")`; downgrade drops children first** — the FK
  is enforced (E2·P1 enabled `PRAGMA foreign_keys=ON` per connection), so `downgrade()` drops
  `workout_statistics` before `workouts` to avoid a dangling-reference / drop-order error on round-trip
  (DB.md §1; epic R5).
- **Constraint/index names come from E2·P1's `naming_convention`** — the models declare `UniqueConstraint`/
  `Index` and let `Base.metadata`'s `naming_convention` (`uq`/`ix`/`fk`/`pk`) name them, so the
  autogenerated migration is deterministic and the names are assertable in tests (epic E2·P1 bullet 4, R5).
- **One migration for all four ingest tables (not four)** — they form one cohesive ingest unit landing in a
  single PR/phase; a single revision keeps the `down_revision` chain simple and the up/down round-trip
  atomic (epic §3 E2·P2, §4).
- **No data, no write path, in this phase** — tests assert the schema/constraints by attempting raw
  duplicate inserts to prove the UNIQUE rejection (a constraint check, not the `/sync` upsert), but the
  idempotent `ON CONFLICT(uuid) DO NOTHING` write path itself is E5 (DB.md §6; epic §7).

## Risks

- **`uuid` made `NOT NULL` (or a plain PK) by mistake** → seeded rows (NULL uuid) can't be inserted —
  mitigation: model declares `uuid` `nullable=True` with a separate `UNIQUE` constraint; a test inserts
  **two** rows with `uuid=NULL` into `records` (and `workouts`) and asserts both succeed, then asserts a
  duplicate **non-NULL** uuid is rejected (DB.md §1; epic R4/R5).
- **A UNIQUE/index/FK is dropped or mis-named in autogenerate** → epic R5 violated silently — mitigation:
  tests introspect the migrated DB (`PRAGMA index_list`/`index_info`, `PRAGMA foreign_key_list`,
  `sqlite_master`) and assert `records` has `UNIQUE(uuid)` + `(type,start_date)` + `(start_date)`,
  `workouts` has `UNIQUE(uuid)`, `workout_statistics` has `(workout_id,type)` and the FK to `workouts(id)`
  (epic R5, §4).
- **FK not enforced** (SQLite defaults `foreign_keys` OFF per connection) → orphan `workout_statistics`
  rows — mitigation: E2·P1's `set_sqlite_pragmas` listener issues `PRAGMA foreign_keys=ON`; a test inserts
  a `workout_statistics` row with a non-existent `workout_id` over a `get_engine()` connection and asserts
  an `IntegrityError` (DB.md §1; E2·P1 decision).
- **Round-trip fails on the FK drop order** — mitigation: `downgrade()` drops `workout_statistics` before
  `workouts`; the Alembic `upgrade head`→`downgrade base`→`upgrade head` test proves the round-trip and
  that all four tables are gone after `downgrade base` (epic §4, §6).
- **Wrong column type** (e.g. `apple_stand_hours` stored REAL not INTEGER, or a timestamp as `DATETIME`) —
  mitigation: a test reads `PRAGMA table_info` per table and asserts the declared SQLite type affinity
  (INTEGER for `id`/`apple_stand_hours`(+goal)/`workout_id`, REAL for values, TEXT for timestamps/text)
  (DB.md §1; epic §4).
- **Migration accidentally targets `baseline.db` / leaks a dropped-stack dep** — mitigation: reuse E2·P1's
  `alembic/env.py` (settings-owned URL, no `baseline` reference); `! grep -rn baseline alembic` and
  `! grep -REn "psycopg|pgvector|celery|redis|supabase|vecs" app` stay empty (DB.md §0; ARCHITECTURE §1).
- **Models not registered on `Base.metadata`** → autogenerate emits an empty migration — mitigation:
  `models/__init__.py` imports all four; a test asserts `set(Base.metadata.tables) ⊇ {records, workouts,
  workout_statistics, activity_summary}` (epic E2·P2).

## Acceptance Criteria

- [ ] **Four ingest tables created:** after `alembic upgrade head` on a temp **file** DB, `sqlite_master`
      contains `records`, `workouts`, `workout_statistics`, `activity_summary` (plus `alembic_version` and
      any E2·P1 tables — none yet) (`tests/database/test_ingest_migration.py`). (epic §3, §4; DB.md §1)
- [ ] **Round-trip:** `upgrade head` → `downgrade base` → `upgrade head` succeeds on a temp file DB; after
      `downgrade base` none of the four ingest tables exist; the FK drop order (`workout_statistics`
      before `workouts`) does not error. (epic §4, §6)
- [ ] **`records` columns & types:** `PRAGMA table_info(records)` shows `id` INTEGER PK, `uuid` TEXT
      (nullable), `type` TEXT NOT NULL, `unit` TEXT, `value` REAL, `value_text` TEXT, `source_name`/
      `source_version`/`device` TEXT, `creation_date` TEXT, `start_date` TEXT NOT NULL, `end_date` TEXT,
      `origin` TEXT NOT NULL. (DB.md §1)
- [ ] **`records` indexes:** introspection shows a UNIQUE index on `(uuid)`, a non-unique index on
      `(type, start_date)`, and a non-unique index on `(start_date)`. (epic R5; DB.md §1)
- [ ] **`records.uuid` UNIQUE, NULL-tolerant:** inserting two rows with `uuid=NULL` both succeed; inserting
      two rows with the **same non-NULL** `uuid` raises `IntegrityError`. (DB.md §1; epic R4/R5)
- [ ] **`workouts` columns & types:** `PRAGMA table_info(workouts)` shows `id` INTEGER PK, `uuid` TEXT
      (nullable, UNIQUE), `activity_type` TEXT NOT NULL, `duration`/`total_distance`/`total_energy_burned`
      REAL with their `*_unit` TEXT, `effort_score` REAL nullable, `physical_effort` REAL nullable,
      provenance + `creation_date` TEXT, `start_date` TEXT NOT NULL, `end_date` TEXT, `origin` TEXT NOT NULL.
      (DB.md §1)
- [ ] **`workouts.uuid` UNIQUE, NULL-tolerant:** inserting two `workouts` rows with `uuid=NULL` both
      succeed (the E4 seed path), and inserting two rows with the **same non-NULL** `uuid` raises
      `IntegrityError`. (epic R4/R5; DB.md §1; round-1 #2)
- [ ] **`workout_statistics` FK + index:** `PRAGMA foreign_key_list(workout_statistics)` shows a FK on
      `workout_id` → `workouts(id)`; an index on `(workout_id, type)` exists; inserting a row whose
      `workout_id` does not exist raises `IntegrityError` (FK enforced via E2·P1's `foreign_keys=ON`).
      Columns: `id` PK, `workout_id` INTEGER NOT NULL, `type` TEXT NOT NULL, `start_date`/`end_date` TEXT,
      `sum`/`average`/`minimum`/`maximum` REAL, `unit` TEXT. (DB.md §1; epic R5)
- [ ] **`activity_summary` PK & types:** `date` TEXT is the PRIMARY KEY **and NOT NULL** (`PRAGMA
      table_info` reports `pk=1` and `notnull=1` for `date`; inserting a row with `date=NULL` raises
      `IntegrityError`); `active_energy_burned`(+`_goal`), `apple_exercise_time`(+`_goal`),
      `apple_move_time`(+`_goal`) are REAL; `apple_stand_hours`(+`_goal`) are INTEGER. (DB.md §1; round-1 #1)
- [ ] **Models registered on metadata:** `set(Base.metadata.tables)` includes `records`, `workouts`,
      `workout_statistics`, `activity_summary` after `import app.database.models`. (epic E2·P2)
- [ ] **No baseline / dropped-stack leakage:** `grep -rn baseline alembic` finds nothing new for this
      migration; `grep -REn "psycopg|pgvector|celery|redis|supabase|vecs" app` is empty. (DB.md §0;
      ARCHITECTURE §1)
- [ ] `uv run ruff check .` and `uv run pytest tests/database` pass.
