## Goal

Stand up the runtime-database **engine, WAL, declarative base + naming conventions, Europe/Sofia
period-key/timestamp helpers, and Alembic — all targeting `app.db` only** — so E2·P2/P3 can attach the
nine tables; this phase ships **no tables** of its own.

## Scope

- **`app/database/engine.py`** — a `make_engine(db_path)` factory and a **lazy** cached `get_engine()`
  built from `settings.app_db_path` (E1·P1, never hard-coded; not constructed at import — round-2 #2), a
  `sessionmaker` (`SessionLocal`), a `get_session()` provider, and a **side-effect-free** `set_sqlite_pragmas`
  **`connect` event listener** that issues `PRAGMA journal_mode=WAL` **and** `PRAGMA foreign_keys=ON` on
  every new DBAPI connection (DB.md §0; epic R1; ARCHITECTURE §1).
- **`app/database/base.py`** — declarative `Base` over a `MetaData` carrying a **`naming_convention`**
  (`ix`/`uq`/`ck`/`fk`/`pk`) so future autogenerate produces stable, deterministic constraint/index
  names (epic E2·P1 bullet 4, R5).
- **`app/core/time.py`** — Europe/Sofia period-key helpers: `period_date(dt)` → `YYYY-MM-DD` and
  `iso_week(dt)` → `YYYY-Www`, both resolved through `zoneinfo.ZoneInfo("Europe/Sofia")` (DST-aware);
  plus timestamp helpers that **parse and preserve the per-sample offset** HealthKit emits (epic R2;
  DB.md §0; ARCHITECTURE §4). Never inject a fixed offset.
- **`alembic.ini` + `alembic/env.py` + `alembic/script.py.mako` + `alembic/versions/`** — Alembic
  configured to target **`app.db` ONLY** (URL from `settings.app_db_path`), with `Base.metadata` as the
  autogenerate target; an **initial (empty) migration** that round-trips (epic E2·P1, §4, §6).
- **`app/database/__init__.py`** — re-export `make_engine`, `get_engine`, `set_sqlite_pragmas`,
  `SessionLocal`, `get_session`, `Base`, `metadata`. **No** module-level `engine` is exported — the runtime
  engine is lazy via `get_engine()` (round-2 #2).
- **`pyproject.toml`** — add `alembic` and `tzdata` (portable Europe/Sofia tz data) to deps;
  `[tool.alembic]`/script location wiring as needed.
- **Tests** (`tests/database/`, `tests/core/`) — WAL pragma active on a live connection; period-key
  helpers correct across a **DST boundary** (EET↔EEST) **and** a non-Sofia **travel offset**; Alembic
  `upgrade`→`downgrade`→`upgrade` round-trip on a temp **file** DB.

## Out of Scope

- **The nine tables** — `records`, `workouts`, `workout_statistics`, `activity_summary` (E2·P2);
  `daily_metrics`, `checkins`, `strength_tests`, `plans`, `suggestions` (E2·P3). This phase creates
  **zero** tables; the initial migration is empty (epic §3, §7).
- **The R5 UNIQUE/index/FK constraints** themselves — defined with their tables in E2·P2/P3 (this phase
  only guarantees their *names* will be deterministic via the naming convention).
- **Writing data** (E5 `/sync`), **computing `daily_metrics`** (E6), **`profile.yaml`** (E3), **seeding
  from `baseline.db`** (E4). `baseline.db` is never opened here (epic §7; DB.md §0).
- **Dropped stack** — Postgres/pgvector, Celery, Redis, Supabase, streaming, RAG/`vecs`
  (ARCHITECTURE §1 stack note).

## Research Summary

`app.db` is the **only** database the running API touches; `baseline.db` is a read-only build input,
regenerated by `build_db.py` (`DROP TABLE …`) and never opened at runtime — so Alembic and the engine
must target `app.db` exclusively (DB.md §0; ARCHITECTURE §3). It runs in **SQLite WAL** mode, Alembic-owned
and `litestream`-backed, so WAL must actually be on — set via a SQLAlchemy `connect` event listener
issuing `PRAGMA journal_mode=WAL` (ARCHITECTURE §1; epic R1). All timestamps are stored as **ISO-8601
TEXT carrying the per-sample offset HealthKit emits** (Europe/Sofia is `+02:00`/EET winter, `+03:00`/EEST
summer, plus travel — never hard-coded), and period keys (`date`, `iso_week`→`YYYY-Www`) are derived
through the **`Europe/Sofia` tz database** via `zoneinfo`, DST-aware (epic R2; DB.md §0; ARCHITECTURE §4).
A `naming_convention` on the declarative `MetaData` makes E2·P2/P3 autogen diffs deterministic for the R5
constraints. Full keep/scope matrix and citations in [`RESEARCH.md`](./RESEARCH.md).

## Decisions

- **Period-key/timestamp helpers live in `app/core/time.py`, not `app/database/time.py`** — period keys
  are a domain/time concern used by **many** epics (E5/E6/E10/E11), not a DB-engine concern; keeping them
  in `core` avoids importing the DB layer just to format a week key (runbook NOTES allow either; resolved
  to `core`).
- **WAL set via a `connect` event listener, not a one-off at startup** — so **every** pooled connection
  is in WAL, and fresh temp DBs in tests get it too. The same listener also issues `PRAGMA
  foreign_keys=ON` — SQLite defaults FK enforcement **OFF per connection**, and E2·P2 adds the FK
  `workout_statistics.workout_id → workouts(id)`, so enabling it now is the right home (DB.md §1; epic R1).
  The listener (`set_sqlite_pragmas`) is a **side-effect-free, importable** function so Alembic's `env.py`
  reuses it without constructing the runtime engine (round-1 #1).
- **Runtime engine is lazy (`get_engine()`), not built at import** — building a module-level engine at
  import would force `app_db_path` to resolve the moment any module (including Alembic's `env.py`, which
  imports the pragma helper) is loaded, and could bind the wrong DB before a test override applies. A
  cached lazy `get_engine()` reads `settings.app_db_path` on first use instead (round-1 #1, #4).
- **Alembic URL is owned by settings; static `sqlalchemy.url` is ignored; only an explicit test override**
  — the two-DB lifecycle split is load-bearing; pointing Alembic at the build input would let a migration
  drop or mutate read-only corpus. So `resolve_url()` returns `sqlite:///{settings.app_db_path}` in
  production, ignores any `.ini` `sqlalchemy.url` (a stale value can't redirect a migration), and accepts
  only the explicit `config.attributes["test_db_url"]` test override; `env.py` never names `baseline.db`
  (DB.md §0; epic E2·P1; round-1 #2).
- **The initial migration is empty** — this phase defines no tables (E2·P2/P3 do). An empty revision is
  valid, still exercises the `upgrade/downgrade` round-trip, and proves the Alembic wiring +
  `Base.metadata` target + naming-convention are sound without pre-empting later phases (epic §3, §4).
- **`Base.metadata` carries a `naming_convention` (`ix`/`uq`/`ck`/`fk`/`pk`)** — gives stable,
  deterministic names so the R5 UNIQUE/index/FK constraints added in E2·P2/P3 autogenerate clean,
  reviewable diffs across machines (epic E2·P1 bullet 4, R5).
- **Add `tzdata` as a dependency** — `ZoneInfo("Europe/Sofia")` needs the IANA tz database; some
  containers/CI lack the system copy, so the portable PyPI fallback guarantees DST-aware period keys
  everywhere (epic R2).
- **Timestamps stored as raw ISO-8601 TEXT, offset preserved verbatim** — never normalized to UTC or a
  fixed `+03:00`; they sort correctly as TEXT and stay debuggable. `store_ts(s)` validates and returns the
  **exact** string; helpers parse the offset present on the input, they do not impose one (DB.md §0;
  ARCHITECTURE §4; epic R2).
- **Period-key helpers reject naive datetimes (no host-tz fallback)** — `to_sofia`/`period_date`/`iso_week`
  guard `tzinfo`/`utcoffset` and raise on a naive `datetime`; `astimezone()` on a naive value would
  silently use the host local timezone, producing machine-dependent cache keys across dev/CI/containers.
  Period keys must be reproducible, so aware-only is enforced (round-2 #3; DB.md §0; ARCHITECTURE §4).

## Risks

- **Alembic accidentally targets `baseline.db` or a stray default path** — mitigation: `env.py`'s
  `resolve_url()` reads `settings.app_db_path` (ignoring any static `.ini` `sqlalchemy.url`, round-1 #2);
  a test asserts the resolved URL is the app path (via the explicit test override), that a planted bogus
  `sqlalchemy.url` is ignored, and that the string `baseline` appears nowhere in
  `alembic/env.py`/`alembic.ini` (`! grep -rn baseline alembic alembic.ini`). (DB.md §0; epic E2·P1.)
- **Module-level engine binds settings/DB too early or before a test override** — mitigation: the runtime
  engine is lazy (`get_engine()`); `set_sqlite_pragmas` is side-effect-free; an import-isolated test proves
  `import app.database.engine` with `app_db_path` cleared does not raise and that `get_engine().url.database`
  follows an overridden `app_db_path` (round-1 #1, #4).
- **WAL silently not applied** (listener mis-wired / wrong event / in-memory DB masking it) — mitigation:
  a test opens a real **file** engine and asserts `PRAGMA journal_mode` returns `wal` on a fresh
  connection, and `PRAGMA foreign_keys` returns `1` (epic R1; runbook §5).
- **Hard-coded offset slips in** (assuming `+03:00`) — mitigation: period-key tests cross a **DST
  boundary** (a late-March EET→EEST instant near `02:00`/`03:00`) **and** feed a **non-Sofia travel
  offset** (e.g. a `+09:00` timestamp), asserting the Sofia-local `date`/`iso_week` — proving the helper
  converts through the tz db, not the literal offset (epic R2, §6; ARCHITECTURE §4).
- **ISO-week formatting drift** (year-boundary weeks `W01`/`W52`/`W53`, zero-padding) — mitigation: tests
  assert `YYYY-Www` zero-padded and a year-boundary case (e.g. a date whose ISO week belongs to the
  previous/next ISO year) (DB.md §4 `2026-W23` example).
- **`zoneinfo` tz data missing in CI/container** → `ZoneInfoNotFoundError` — mitigation: `tzdata` is a
  declared dependency; a test imports `ZoneInfo("Europe/Sofia")` and resolves it.
- **Round-trip fails on an empty migration** (down_revision/version table edge cases) — mitigation: the
  Alembic test runs `upgrade head`→`downgrade base`→`upgrade head` on a temp file DB and asserts the
  `alembic_version` row is `head` at the end and absent after `downgrade base` (epic §4, §6).

## Acceptance Criteria

- [ ] **WAL active (both paths):** (a) opening the **runtime** file engine and running `PRAGMA
      journal_mode` on a fresh connection returns `wal`, `PRAGMA foreign_keys` returns `1`
      (`tests/database/test_engine_wal.py`); **and** (b) after `alembic upgrade head` on a temp file DB, the
      **migrated** file — opened with a **raw `sqlite3.connect` (no listener, not via `make_engine`)** —
      reports `PRAGMA journal_mode == 'wal'` (`tests/database/test_alembic.py`), proving `env.py` attaches
      `set_sqlite_pragmas` during the migration (a listener-bearing inspection connection would mask a
      broken `env.py`). (epic R1, §4; round-2 #1; round-3 #1)
- [ ] **Engine sourced from settings (import-isolated):** the runtime engine is **lazy** (`get_engine()`,
      not built at import); an import-isolated test sets `app_db_path` to a temp path, clears the
      settings/engine caches, and asserts `get_engine().url.database` equals that path — proving it reads
      `settings.app_db_path`, not a literal or the `make_engine` arg. (round-1 #4)
- [ ] **Alembic targets `app.db` only:** `grep -rn baseline alembic alembic.ini` finds nothing; with no
      test override, `resolve_url()` equals `sqlite:///{settings.app_db_path}`; **a stale/static
      `sqlalchemy.url` is ignored** (negative test), so a stray `.ini` can't redirect a migration; the only
      override is the explicit test-only `config.attributes["test_db_url"]`. (DB.md §0; round-1 #2)
- [ ] **Round-trip:** `upgrade head` → `downgrade base` → `upgrade head` succeeds on a temp **file** DB;
      `alembic_version` holds `head` afterwards and is empty after `downgrade base`
      (`tests/database/test_alembic.py`). (epic §4, §6)
- [ ] **No tables yet:** after `upgrade head`, the DB contains the `alembic_version` table and **no**
      application tables (initial migration is empty). (epic §3, §7)
- [ ] **Declarative base + naming convention:** `Base.metadata.naming_convention` defines `ix`/`uq`/`ck`/
      `fk`/`pk` keys (unit test on the convention map). (epic E2·P1 bullet 4)
- [ ] **Period date (Europe/Sofia):** `period_date(dt)` returns the Sofia-local `YYYY-MM-DD`, correct
      across a DST boundary **and** for a non-Sofia travel offset (`tests/core/test_time.py`). (epic R2, §6)
- [ ] **ISO week (`YYYY-Www`):** `iso_week(dt)` returns the Sofia-local zero-padded `YYYY-Www` (e.g.
      `2026-W23`), correct across a DST boundary, a travel offset, and an ISO year-boundary week. (DB.md §4)
- [ ] **Timestamp stored verbatim (string identity):** `store_ts(s) == s` returns the **exact** original
      ISO-8601 string for the doc/HealthKit offset forms (`+02:00`, `+03:00`, compact `+0300`, a non-Sofia
      offset, and a fractional-seconds case) — no offset reformatting, no UTC normalization; `parse_ts`
      additionally preserves the offset and raises on a naive string. (epic R2; DB.md §0; round-1 #3)
- [ ] **Naive datetime rejected:** `to_sofia`/`period_date`/`iso_week` raise `ValueError` on a naive
      `datetime` (no host-tz fallback → reproducible cache keys). (round-2 #3)
- [ ] **tz data available:** `ZoneInfo("Europe/Sofia")` resolves (tzdata dep present). (epic R2)
- [ ] **No dropped-stack deps:** `grep -REn "psycopg|pgvector|celery|redis|supabase|vecs" app pyproject.toml`
      is empty. (ARCHITECTURE §1 stack note)
- [ ] `uv run ruff check .` and `uv run pytest tests/database tests/core/test_time.py` pass.
