Overview

Make profile.yaml the single, validated source of truth for every numeric constant — a typed Pydantic loader mirroring DB.md §5's five sections, with cap/monotonicity/contiguity validation, the §5 example shipped verbatim, and accessors for the zone/nutrition constants and constitution_version.

Goal

This phase ships the typed loader + example file only. It does not render the constitution (that is E3·P2) and does not derive the constants from baseline.db (E4). The model exposes only static fields — every live/derived value stays in app.db.
  • Epic — E3 — Profile & Constitution, phase P1. Source of truth: epics/E03-profile-constitution.md (§2 R1–R3, §3 E3·P1, §4 acceptance, §6 validation, §7 out-of-scope).
  • Grounded in — DB.md §5 (the profile.yaml block, five sections, every field, the example yaml verbatim, the static-vs-live split table + footnote ¹) and DB.md §0 (profile.yaml is a file, NOT a table — 9 tables in app.db, no profile table).
  • Consumers — LLM.md §2: the constitution renders fresh each call from these constants (maxHR, baselines, zones, cadence cue, nutrition constants — E9), and constitutionVersion stamps each brief; E8's macro/zone math reads the nutrition/zone constants.
  • Builds on — E1·P1 (app/core/settings.py typed pydantic-settings) — though this loader is internal config, not a camelCase wire model, so it does not inherit the camelCase wire base.

Scope vs Out-of-Scope

In scope this phase
  • app/core/profile.py — six typed Pydantic models mirroring §5 exactly (Athlete, Thresholds, Zones, Nutrition+CarbsPerKg, Meta, Profile), all extra="forbid".
  • Validators (R2): caps, monotonic + contiguous zones, fat low≤high, max_hr>rhr.
  • load_profile(path) loader — yaml.safe_load, clear FileNotFoundError / parse errors, default PROFILE_PATH.
  • Accessors: zone_bounds() + nutrition constants (E8), constitution_version (E9) — static fields only.
  • profile.yaml at app/repo root — §5 example verbatim.
  • tests/core/test_profile.py — valid load, every negative case, static-vs-live guard.
Out of scope later epics
  • Rendering the constitution — HEALTH-CONSITTUTION.md → Jinja2 system prompt is E3·P2.
  • Deriving constants from baseline.db (bootstrap write) is E4·P2; monthly RecomputeConstants rewrite is E8·P5 + E10.
  • Live/derived values — current weight, 30d HRV/RHR baselines, per-day metrics live in app.db (daily_metrics); not modeled here.
  • The macro/zone math & system prompt that consume these constants — E8 / E9.
  • Wiring into pydantic-settings/env beyond a path — settings owns env (E1·P1).
  • Dropped stack — Postgres/pgvector, Celery, Redis, Supabase, streaming, RAG/vecs.

Risks & mitigations

riskmitigation
Field names drift from §5 → the constitution template (E3·P2) or macro engine (E8) reads a key that does not existEvery field name mirrors the §5 key exactly; extra="forbid" rejects strays; the loader test loads the shipped example (§5 verbatim), so any rename breaks the test.
A cap or monotonicity check is silently skipped (validator not wired, or < vs ≤)One negative test per rule (deficit>0.20, protein>2.0, non-monotonic, non-contiguous, missing carb key, fat low>high, max_hr≤rhr) asserts a ValidationError naming the field.
Contiguity vs monotonicity conflated — a monotonic-but-gapped set (z1.high < z2.low) passes a monotonic-only checkThe validator asserts both; a dedicated test feeds a monotonic but non-contiguous set and asserts rejection.
A live/derived value leaks into the file/model (current weight, rolling baselines) → static-vs-live split violated, stale numbers reach the brainProfile models only §5 static fields; a test asserts body_weight/current_weight/hrv_30d/rhr_30d/readiness absent; extra="forbid" would reject them if added.
YAML scalar coercion surprises (rest_high: 2.5 as float, dates parsed by the loader)Use yaml.safe_load, type numeric fields explicitly (int/float), type computed_at as date, assert parsed types in the load test.
Default-path resolution wrong in tests/runtime (cwd-relative vs package-relative)Default resolved from a module-level package anchor (app/repo root); load_profile(path=…) overrides; negatives pass explicit temp paths, one test loads the real shipped file via its resolved default.
Scope creep into rendering/derivationScope is loader + example + accessors only; rendering is E3·P2, derivation is E4.

Research summary

Static-vs-live split is load-bearing (epic R3; DB.md §5 table + ¹). Static/monthly-frozen in the file: age/sex/height/goal-weight, max_hr/rhr_baseline/hrv_baseline_ms/easy_hr_cap/cadence cues, the Z1–Z5 bpm bounds, and the nutrition constants. Live (in daily_metrics, NOT the file): current weight, the 30d HRV/RHR rolling baselines, and per-day metrics. rhr_baseline/hrv_baseline_ms in the file are the monthly anchors used to derive zones — readiness reads the live rolling values from daily_metrics, not these (DB.md §5 ¹).

task 002 · behaviour

Loader and validation (caps, monotonic zones)

Add the YAML loader (load_profile) and the validators that enforce §5's constraints — deficit ≤ 0.20, protein ≤ 2.0, fat low ≤ high, max_hr > rhr, and zone bounds monotonic and contiguous — so a bad file fails loudly at load with a clear, field-named error.

Suggested commit: feat(core): add profile.yaml loader and constant validation · Depends on: TASK-001.

Files

pathchangecontents

Validators & loader

model / fnrule
Zones@model_validator(mode="after"): each zN=(low,high) has low < high; lows strictly increasing (z1.low < … < z5.low); contiguity z1.high == z2.low, z2.high == z3.low, z3.high == z4.low, z4.high == z5.low. Raise ValueError naming the offending boundary.
Nutritiondeficit_pct: Field(le=0.20) and protein_g_per_kg: Field(le=2.0), plus @model_validator(mode="after") asserting fat_g_per_kg_low <= fat_g_per_kg_high.
Thresholds@model_validator(mode="after") asserting max_hr > rhr_baseline.
load_profile(path)module-level: resolve path (default PROFILE_PATH; overridable), yaml.safe_load, construct Profile(**data). Let ValidationError propagate; raise a clear FileNotFoundError when the path is missing; wrap a YAML parse error with a readable message.
PROFILE_PATHmodule-level Path from a package anchor — Path(__file__).resolve().parents[2] / "profile.yaml", NOT cwd-relative.

Acceptance

  • load_profile(<valid temp yaml>) returns a Profile; values match the file.
  • load_profile(<missing path>) raises a clear FileNotFoundError.
  • deficit_pct = 0.25 → ValidationError naming deficit_pct / the 0.20 cap; 0.20 accepted (boundary inclusive).
  • protein_g_per_kg = 2.5 → ValidationError naming protein_g_per_kg; 2.0 accepted.
  • Non-monotonic zones (a zN.low >= zN.high, or lows not strictly increasing) → ValidationError.
  • Non-contiguous zones (z1=[96,124], z2=[125,150] → z1.high != z2.low) → ValidationError.
  • fat_g_per_kg_low = 1.2, fat_g_per_kg_high = 1.0 → ValidationError.
  • max_hr = 50, rhr_baseline = 58 (max_hr ≤ rhr) → ValidationError.

Watch out: caps are inclusive (le= not lt=). Zones must be both monotonic and contiguous — the §5 example is exactly contiguous (z1:[96,125] z2:[125,150] z3:[150,167] z4:[167,177] z5:[177,192]). Resolve PROFILE_PATH from a package anchor, not cwd.
