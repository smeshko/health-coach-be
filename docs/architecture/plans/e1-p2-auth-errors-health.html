Auth, error envelope & health

Make the FastAPI process authenticated and observable: one error envelope for every non-2xx, a reusable bearer-token auth dependency, and an unauthenticated GET /health liveness endpoint.

Epic & dependency context

Epic E1 — Foundation & API Skeleton, phase P2. Source of truth: epics/E01-foundation.md (§3 E1·P2, §4 acceptance), grounded in ARCHITECTURE.md §1 and MODELS.md "Conventions" / "Errors".

Scope vs out-of-scope

In scope ships now
  • Error envelope (app/api/errors.py) — CamelModel Error { code, message, detail } wrapped as { "error": { … } }, with handlers for RequestValidationError, HTTPException, and a catch-all Exception.
  • Auth dependency (app/api/auth.py) — reads Authorization: Bearer <token>, constant-time compare vs get_settings().api_token; failure → HTTPException(401).
  • GET /health (app/api/routes/health.py) — unauthenticated liveness { status: "ok", serverTime } with a DST-aware offset.
  • Protected probe route — guarded by the auth dependency to demonstrate 401-without / 200-with the token.
  • Wiring — register handlers + routers inside create_app(), keeping P1's fail-fast settings load intact.
  • MODELS update — add internal_error to MODELS "Errors" in the same PR (no deferred drift).
Out of scope later epics
  • Real domain endpoints /sync, /brief/daily, /brief/weekly (E5/E10/E11) — only a throwaway probe ships here.
  • Codes brief_generation_failed / upstream_timeout are defined in the enum now, but the paths that raise them arrive in E9/E10/E11.
  • Workflow engine primitives (E1·P3); DB models / migrations (E2); LLM (E9); Docker / Langfuse (E12).
Not deferred: the internal_error fallback is wired and documented in MODELS in this PR — unlike the two unraised codes above.

Research summary

  • Envelope is fixed by MODELS "Errors" — a single wrapper { "error": { code, message, detail } } over all non-2xx; code from a closed set; detail is string | null (nullable, optional).
  • No documented code for unmapped / unhandled 500 — so this phase adds one named fallback internal_error (a deliberate extension, added to MODELS this PR) rather than an open status-derived code.
  • Auth is one long-lived bearer token in the Authorization header, never the body; single user, no tenancy (MODELS "Conventions → Auth"; epic §2 R3).
  • Timestamps must be ISO-8601 carrying the actual device offset — Europe/Sofia is +02:00 winter / +03:00 summer; serverTime already appears that way in SyncResponse.
  • Process shape — a single synchronous FastAPI app (ARCHITECTURE §1). P1 already ships create_app(), the api_token setting, and CamelModel.

STATUS_TO_CODE — one source of truth

Each handled status maps to (code, default_public_message); any status not in the table falls back to (internal_error, "An internal error occurred."). message is always a non-empty string, so a no-detail HTTPException never yields message=None (round-3 #1).

statuscodedefault messagehandler
422validation_errorfixed public message; detail summarises the failuresRequestValidationError
401unauthorized"Authentication required."HTTPException
404not_found"Resource not found."HTTPException
any otherinternal_error"An internal error occurred."HTTPException (table default)
500internal_errorfixed public message, detail: nullcatch-all Exception
Detail rule: for HTTPException, detail is set from exc.detail only when it is a non-empty string; exc.detail is never used as the sole message source. The catch-all leaks no internals (detail: None).

Acceptance

  • Wire shape — Error serialises camelCase; ErrorResponse wraps it as { "error": { … } } matching MODELS keys.
  • Nullable detail — detail accepts both omission and explicit null on input.
  • 404 — a route raising HTTPException(404) and an unknown path both return the not_found envelope (not FastAPI's default).
  • 422 — a body/param validation failure returns validation_error.
  • 500 — a bare Exception returns internal_error, a fixed message, detail == null, no leak (raise_server_exceptions=False).
  • Unmapped status — an HTTPException(400) returns internal_error (table default), never a code outside ErrorCode.
  • No-detail paths — a no-detail 401/404/400 still yields a non-empty message and detail == null (round-3 #1).
  • Closed enum — constructing Error with a code outside the set raises a ValidationError.
  • Doc parity — MODELS "Errors" lists internal_error, so every ErrorCode member is documented.

Bearer-token auth dependency

A reusable FastAPI dependency that authenticates requests against the single long-lived bearer token, raising a 401 the error handlers render as the unauthorized envelope.

Goal: one importable require_auth dependency, constant-time token check, that gates any route via Depends(require_auth) and builds no JSON itself. Suggested commit: feat(api): add bearer-token auth dependency.

Files

pathchangewhat
app/api/auth.pynewrequire_auth(...) — reads the Authorization header (via HTTPBearer(auto_error=False) or a direct read), requires the Bearer <token> scheme, compares constant-time (secrets.compare_digest) vs get_settings().api_token. Missing header / wrong scheme / wrong token → HTTPException(401). On success returns the token / a sentinel.
tests/test_auth.pynewGuarded route: no header / wrong token / non-Bearer → 401 envelope; correct token → 200; reusability on a second route.

Acceptance

  • Gate fires — a route under Depends(require_auth) returns 401 + unauthorized envelope when the header is absent, the scheme is not Bearer, or the token is wrong.
  • Pass-through — the same route returns 200 when Authorization: Bearer <api_token> matches get_settings().api_token.
  • Constant-time — comparison uses secrets.compare_digest; wrong-token still returns 401.
  • Reusable — attaching require_auth to a second route also gates it (not hard-wired to one endpoint).

now_sofia — instant-preserving, never a relabel

The helper takes an aware UTC instant from an injected clock (default datetime.now(timezone.utc)) and converts via .astimezone(ZoneInfo("Europe/Sofia")) — the offset always comes from the tz database; there is no timezone(timedelta(...)) fixed-offset construction anywhere.

Inject UTC source
  • Tests override only the UTC clock source, not the conversion.
  • 2026-01-15T12:00:00Z → 2026-01-15T14:00:00+02:00 (winter).
  • 2026-07-15T12:00:00Z → 2026-07-15T15:00:00+03:00 (summer).
  • Assert the full converted wall-clock, not just the offset.
Reject wrong impls
  • A fixed timezone(timedelta(...)) — same offset year-round.
  • A .replace(tzinfo=ZoneInfo(...)) relabel — right offset, wrong wall-clock.
  • Monkeypatching now_sofia away — only proves serialization.
SOURCE GUARDgrep requires astimezone(ZoneInfo("Europe/Sofia")) present and rejects timezone(timedelta / .replace(tzinfo= / datetime.timezone( for serverTime (resolves round-2 #2, round-3 #2).

Acceptance

  • Unauthenticated health — GET /health with no header → 200, status == "ok", serverTime parses to a timezone-aware datetime; the full converted wall-clock matches per season (DST proof through the production conversion).
  • camelCase key — serverTime is the wire key (model inherits CamelModel).
  • Probe gate — the protected probe → 401 (unauthorized) without / with a wrong token, 200 with the correct Bearer <api_token> — the end-to-end auth demonstration.
  • Health is open — /health is reachable without the auth dependency; no 401 is ever returned for it.
