Decisions

  • Port (not import) the Launchpad core/, trimmed — the Launchpad is a sibling boilerplate, not a dependency; we own the primitives and strip Langfuse / streaming / concurrency / Celery so the kept-stack invariant (ARCHITECTURE §1) holds in our tree.
  • AgentNode is an abstract placeholder, no provider/LLM wiring — real PydanticAI Agent/model construction is E9. pydantic_ai is kept stack and NOT durably banned; the phase-scoped forbid is narrower: app/core/nodes.py must not yet import pydantic_ai / boto3 / google.
  • The safety-gate short-circuit runs its terminal node, then stops — the router routes to a terminal override (e.g. RestDayNode) whose process() writes the code-only REST brief and calls ctx.stop_workflow(); the runner breaks before downstream nodes. The router itself does not stop first (that would skip the brief).
  • TaskContext is plain snake_case BaseModel, not the camelCase wire base — it is internal engine state, never serialized to the client (MODELS "Conventions → Casing"); camelCase brief payloads are separate response models in later epics.
  • Keep both sync run() and async run_async() — workflows are invoked synchronously inline from endpoints, but nodes' process() is async; run() wraps asyncio.run while run_async() lets an async route await it.
  • Drop concurrent_nodes — single-user synchronous flows never fan out concurrently; carrying it would be dead surface.
  • Keep WorkflowValidator + add is_router↔BaseRouter type-check — is_router=True on a non-BaseRouter node must be rejected at construction, else it passes the fanout rule but blows up at runtime with AttributeError.
  • Constrain router output to the validated DAG — a router's returned next node (route or fallback) must be one of the current node's declared connections; _handle_router rejects an undeclared target so routing can't jump off the DAG at runtime.

Node and RouterNode base types

The deterministic Node base and the conditional-branch/short-circuit RouterNode/BaseRouter primitives, operating over TaskContext (ARCHITECTURE §5 node legend).

Goal. Add the deterministic Node base and the conditional-branch/short-circuit RouterNode/BaseRouter primitives. Suggested commit: feat(core): add Node and RouterNode base types.

The three primitives this task ships

Node(ABC)DATAinner OutputType(BaseModel); save_output/get_output; node_name; abstract async process(ctx); async cleanup() no-op
↓
RouterNode(ABC)ROUTERabstract determine_next_node(ctx) -> Node | None; node_name/save_output/get_output as base
↓
BaseRouter(Node)ROUTERholds routes: list[RouterNode] + fallback: Node | None; route(ctx) assigns ctx to each sub-router, returns first non-None next node else fallback; process() is a no-op
Ported from Launchpad core/nodes/base.py and core/nodes/router.py. Re-exports added to app/core/__init__.py for Node, RouterNode, BaseRouter. Tests in tests/core/test_nodes.py.

Acceptance

  • Abstractness + run — Node cannot be instantiated without process; a concrete Node runs via await node.process(ctx) and returns the TaskContext.
  • Output round-trip — save_output(model) stores under node_name; get_output(NodeClass) returns it; a missing node returns None.
  • Router selection + fallback — BaseRouter.route(ctx) returns the first matching sub-router's node, assigns ctx to each before evaluating, and returns fallback when none match (and None when no fallback).
  • Router only routes — it does not stop — determine_next_node only returns the next node (the terminal override, e.g. RestDayNode); it does not call ctx.stop_workflow(). The stop is the terminal node's process() job. A plain Node.process() calling ctx.stop_workflow() is enough to show the flag is observable here; the runner-level "terminal runs, downstream skipped" assertion is TASK-004.
  • No leak — no boto3/google/Langfuse imports (and no pydantic_ai in nodes.py this phase).
Terminal-then-stop. The router routes to the terminal; the terminal node's process() writes its output and calls ctx.stop_workflow() — so the gated REST brief is still produced (ARCHITECTURE §2/§5, E11). The router must not stop before the terminal runs. Routing edges are declared in the WorkflowSchema (TASK-004), which additionally constrains the returned class to the declared connections.

Stop semantics — terminal-then-stop

The §2 safety-gate pattern the runner must support: the router routes to a terminal that writes a code-only brief and then stops — the LLM is never consulted.

SafetyGateRouterROUTERreads context, routes to RestDayNode — does not stop
└─ routes to → RestDayNode (terminal override)
↓
RestDayNodeDATAprocess() writes the REST brief and calls ctx.stop_workflow()
↓
AgentNodeLLMSKIPPED — loop breaks at top of next iteration (should_stop)
SAFETY GATEStop is checked at the top of the loop, so the routed-to terminal always runs first. The runner must never short-circuit before a routed-to node — that would skip the §2 gated REST brief (ARCHITECTURE §2/§5, E11).

_handle_router DAG-constraint — harden vs Launchpad

Off-DAG guard. After BaseRouter.route(ctx) returns a node, map it to its class and reject (raise ValueError) if that class is not among the current node's declared connections. None/fallback-to-None ends the walk. Launchpad does no such check — without it a buggy route/fallback could hit an undeclared node (mid-run KeyError / unreviewed path).
