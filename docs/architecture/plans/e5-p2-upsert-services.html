Idempotent upsert services + SyncResponse

Ship the three ingest upsert services (records / workouts / activity) plus an authenticated POST /sync shell that runs them in one transaction and returns a SyncResponse whose split counts make idempotency observable — re-posting the same payload inserts nothing new.

Goal

Goal: Idempotent upsert services that write the E5·P1 wire models into the E2·P2 ingest tables (records/workouts/workout_statistics by uuid, activity_summary by date) and an authenticated POST /sync endpoint that runs them and returns a SyncResponse whose split upserted-vs-duplicate counts make idempotency observable.

In scope this phase

  • app/services/workout_upsert.py — upsert_workouts: map Workout→Workouts; for net-new only, write statistics[] + zoneMinutes as workout_statistics rows.
  • app/services/activity_upsert.py — upsert_activity: upsert ActivitySummary→activity_summary by the date PK (DO UPDATE); returns activityDaysUpserted.
  • app/api/routes/sync.py — authed POST /sync: one transaction → three services → commit → SyncResponse.
  • Relocate now_sofia to app/core/time.py so /sync and /health share one DST-aware serverTime source.

Out of scope later phases
  • Check-in & strength-test upsert (checkins by date, strength_tests by ISO week) → E5·P3. checkin/strengthTest accepted but not persisted; flags returned false.
  • daily_metrics recompute fan-out → E5·P3 → E6. /sync does no recompute and no readiness.
  • Canonical zone-minutes z1_min…z5_min derived from HR records → E6·P1 (DB.md §2).
  • Wire models / RecordType / whitelist → E5·P1 (consumed here, not defined).
  • Ingest tables / migration → E2·P2 (written into, not defined).
  • Bearer auth / error envelope → E1·P2 (applied, not redefined).
  • Dropped stack — Postgres/pgvector, Celery, Redis, Supabase, streaming, RAG/vecs. Synchronous SQLAlchemy over SQLite (WAL).

Acceptance criteria

The phase's contract — eleven behavioural criteria plus the lint/test gate. Each maps 1:1 to a concrete named test or command in final validation.

Counts & idempotency

  • First sync upserts with correct split counts. upsert_records over a fresh DB → upserted = #whitelisted, duplicate = 0; upsert_workouts → upserted = #workouts, duplicate = 0; upsert_activity → #distinct dates. (epic R5, §4)
  • Replay is idempotent — re-posting inserts nothing new. A second upsert_records/upsert_workouts of the identical batch → upserted = 0, duplicate = N; count(*) on records/workouts/workout_statistics unchanged; end-to-end a second POST /sync → all-duplicate/zero-new. (epic R5, §4; DB.md §1)
  • Overlapping date ranges never double-insert. Two batches whose uuid sets overlap insert each uuid exactly once; the overlap is counted as duplicate. (epic §4; MODELS provenance)

Mapping, whitelist & provenance

  • origin='sync' on every live row. SELECT DISTINCT origin FROM records (and workouts) is {'sync'}. (DB.md §1)
  • Whitelist applied — non-whitelisted records ignored. A batch containing a non-whitelisted (or recognised-but-unstored) records.type stores only the whitelisted rows; the dropped type is absent. (epic R3; DB.md §1)
  • Quantity vs category mapping. A quantity sample → value/unit set, value_text NULL; a category sample (category="asleepDeep") → value_text set, value NULL. (DB.md §1; MODELS HealthRecord)

Workout statistics & activity

  • workout_statistics from statistics[] + zoneMinutes, net-new only. A workout with statistics=[avg_hr,max_hr] and zoneMinutes={z1..z5} yields avg_hr in average, max_hr in maximum plus zone_minutes_z1..z5 rows (sum=<min>, unit="min"), all FK'd; a replay adds zero new rows. (DB.md §1; MODELS Workout/WorkoutStat)
  • activity_summary upsert-by-date refreshes in place. Posting the same date twice with different ring values leaves one row carrying the second values; steps ignored without error. (DB.md §1 "upsert by date")

Endpoint, auth & boundary

  • POST /sync returns a complete SyncResponse with serverTime. With a valid Bearer token → 200 + JSON with camelCase recordsUpserted/recordsDuplicate/workoutsUpserted/activityDaysUpserted, checkinSaved=false, strengthTestSaved=false, and a serverTime that parses as a timezone-aware ISO-8601 datetime. (MODELS; ARCHITECTURE endpoints)
  • Unauthenticated → unauthorized envelope. POST /sync with no token and with a wrong token → 401 + {"error":{"code":"unauthorized",…}}; correct token → 200. (epic §4; E1·P2)
  • No readiness / no daily_metrics recompute here. The route + services import no readiness/recompute/daily_metrics module (grep-asserted), and daily_metrics is untouched after a sync. (MODELS; epic §3, §7)
  • Gate. uv run ruff check . and uv run pytest tests/services tests/api/routes/test_sync.py pass.
