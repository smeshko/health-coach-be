Overview

An offline scripts/build_db.py that streams Apple Health export.xml into the read-only corpus ../db/baseline.db — four raw ETL tables mirroring the app.db ingest shape (minus the runtime deltas), built by an idempotent wholesale rebuild, with a per-table count report.

Goal

This is an OFFLINE BUILD SCRIPT, not FastAPI runtime. It lives at scripts/build_db.py (outside app/), uses only stdlib sqlite3 + xml.etree.ElementTree, and writes baseline.db in the sibling ../db/ directory. baseline.db is never opened at runtime — the runtime reads app.db only.
  • What it does — stream export.xml (memory-bounded iterparse + elem.clear()) into ../db/baseline.db as a raw dump: four tables, an idempotent DROP TABLE IF EXISTS … then recreate, then print a per-table row-count summary for sanity.
  • Epic — E4 — Baseline ETL & Bootstrap, phase P1. Source of truth: epics/E04-baseline-bootstrap.md (§1, §2 R1, §3 E4·P1, §4 acceptance, §6 validation, §7 out-of-scope).
  • Grounded in — DB.md §0 (two-DB split; ISO-8601 TEXT timestamps verbatim), DB.md §1 (the four mirrored ingest tables + the uuid/origin/effort_score/date_components→date deltas baseline.db does not carry), DB.md §6/§7 (build paths; wholesale rebuild), and ARCHITECTURE §3 (raw ETL dump: no PKs / no uuid) + §6 (../db/baseline.db regenerable from export.xml, never opened at runtime).
  • Downstream — E4·P2 derives constants into profile.yaml from this corpus; E4·P3 seeds the trailing 90 days into app.db (with the whitelist, origin='seed', and the date_components→date rename — all at the seed copy, not here).

Scope vs Out-of-Scope

In scope this phase
  • scripts/build_db.py — new offline ETL (stdlib only; no app//FastAPI/SQLAlchemy/Alembic import). --xml/--db CLI overrides default to ../db/export.xml → ../db/baseline.db.
  • Streaming parse — iter_health_elements over ET.iterparse(events=("end",)), dispatch on Record/Workout/ActivitySummary, elem.clear() after each.
  • Schema + writes — init_schema drops+recreates the four raw tables; batched executemany; to_float/to_int coercion.
  • Summary report — summarize(conn) per-table COUNT(*); main() prints it.
  • tests/fixtures/health_export_small.xml — tiny synthetic export with known counts.
  • tests/scripts/ — parser, write, idempotency, and streaming tests (fixture only).
Out of scope later phases
  • Constant derivation → profile.yaml (compute_zones.py, zones, nutrition, meta stamp) — E4·P2.
  • The 90-day seed into app.db + seed↔sync reconciliation, the origin='seed' flag, the type whitelist (R4), and the date_components→date rename — E4·P3.
  • Type-whitelist filtering — baseline.db stores the full raw corpus (all Record types).
  • Runtime additions — records.uuid/origin, workouts.uuid/origin/effort_score/physical_effort, the activity_summary.date PK — all app.db-only (E2·P2).
  • workout_events table — the prior ../db/build_db.py writes it, but it is not in DB.md §1's four mirrored tables — excluded.
  • Running against the real 1.5 GB corpus (a manual op); dropped stack — Postgres/pgvector, Celery, Redis, Supabase, vecs.

Research summary

  • The corpus — baseline.db is the read-only historical dump regenerated wholesale by build_db.py and never opened at runtime; it is renamed from the existing ../db/health.db (1.4 GB), whose schema is the source of truth for the raw shape.
  • Scale forces streaming — ~3.5M records / 925 workouts / 1,346 activity-summary days, 2019→2026; the parser must use iterparse(events=("end",)) + elem.clear(), never ET.parse() of the whole DOM.
  • Element → table map — <Record>→records, <Workout>→workouts, <WorkoutStatistics> (child)→workout_statistics, <ActivitySummary>→activity_summary (confirmed from the export.xml DTD + ../db/health.db schema).
  • Reference impl — the prior standalone ../db/build_db.py pins the raw schema, the iterparse approach, batched inserts, and the total_distance backfill; the new repo-managed script re-homes that logic.
  • Resolved uncertainties — workout_events out of scope (four tables only); total_distance backfill kept (deterministic, idempotent); path resolution via default constants + --xml/--db overrides.
