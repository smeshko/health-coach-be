Overview

Render HEALTH-CONSITTUTION.md into the LLM system prompt by lifting it into a Jinja2 template whose {{ }} placeholders are filled from profile.yaml (via the E3·P1 loader) under StrictUndefined — fresh each call, failing loudly on any missing constant — with the §2 medical block rendered as context, constitution_version surfaced for brief stamping, and a documented seam for injecting live weight at call time (never baked in).

Goal

This phase renders the constitution; it does not derive the constants. Lift the already-templatized rulebook into the package, write the StrictUndefined renderer, surface the version, and add the live-weight injection seam. It does not derive the constants from baseline.db (E4) and does not build the LLM call (E9).
  • Epic — E3 — Profile & Constitution, phase P2. Source of truth: epics/E03-profile-constitution.md (§2 R4–R6, §3 E3·P2, §4 acceptance, §6 validation, §7 out-of-scope).
  • Grounded in — LLM.md §0 (the call envelope — the constitution is the system prompt) and §2 (Jinja2-rendered from profile.yaml: maxHR, RHR/HRV baselines, zones, cadence cue, nutrition constants; caching off; live weight via the user context; constitutionVersion stamps each brief; §2 medical = context) and §5 (caching off at ~2 calls/day).
  • Also — ARCHITECTURE.md §6 (HEALTH-CONSITTUTION.md = a Jinja2 template rendered fresh each call; §2 conditions are context, not a code-enforced layer — fitness app, not a medical device) and DB.md §5 (the profile.yaml block — the exact keys the placeholders bind to; the static-vs-live split).
  • Builds on — E3·P1 (app/core/profile.py: load_profile() -> Profile, Profile.{athlete,thresholds,zones,nutrition,meta}, Profile.zone_bounds(), Profile.meta.constitution_version).

Scope vs Out-of-Scope

In scope this phase
  • app/core/templates/constitution.md.j2 — the templatized rulebook: prose verbatim, numeric constants as {{ … }} bound to Profile paths (athlete.*, thresholds.*, zones.zN[0|1], nutrition.* incl. carbs_g_per_kg.*, and the derived easy_hr_cap - 8). Only numeric constants are templatized.
  • app/core/constitution.py — a module-private StrictUndefined env (autoescape=False, FileSystemLoader at __file__) and render_constitution(profile) -> str rendering fresh each call.
  • constitution_version(profile) -> str — surfaces meta.constitution_version for E9's brief stamp.
  • The live-weight seam — a documented LiveContext / build_user_context stub returning the user-context payload (NOT the system prompt).
  • tests/core/test_constitution.py — renderer tests.
Out of scope later epics
  • Deriving the constants — writing profile.yaml from baseline.db (E4·P2) and the monthly RecomputeConstants rewrite (E8·P5 + E10).
  • The profile loader & its validation — app/core/profile.py is E3·P1 (shipped); this phase consumes it.
  • Building the LLM call — full user-context JSON, the PydanticAI Agent, structured OutputType, retries, brief cache — E9.
  • The macro/zone math that consumes these constants (BMR/TDEE/macro grams from live W, zone-minute bucketing) — E8.
  • The current cadence cue — cadence_current_spm is not rendered; the per-card cadenceSpm is computed by code and fed via the user context — E8 / E9.
  • Prompt caching / cache breakpoints — decided off (a design decision, not a TODO).
  • Auto-regenerating the .j2 from the root .md in a build step — docs-tooling, out of scope.
  • Dropped stack — Postgres/pgvector, Celery, Redis, Supabase, streaming, RAG/vecs.

The environment & renderer

# app/core/constitution.py _env = jinja2.Environment( loader=FileSystemLoader(Path(__file__).parent / "templates"), # rooted at __file__, NOT cwd undefined=StrictUndefined, # fail loud — no silent blanks autoescape=False, # Markdown, not HTML keep_trailing_newline=True, trim_blocks=False, ) TEMPLATE_NAME = "constitution.md.j2" def render_constitution(profile: Profile) -> str: # fresh get_template().render() every call — NO cache return _env.get_template(TEMPLATE_NAME).render( athlete=profile.athlete, thresholds=profile.thresholds, zones=profile.zones, nutrition=profile.nutrition, )
Section objects are passed straight through so thresholds.max_hr, zones.z5[1], nutrition.carbs_g_per_kg.hard_low, etc. resolve directly off the Profile graph — no remap layer. zones.zN are the loader's tuple[int,int] so zN[0]/zN[1] work.

Acceptance

  • Fills from the shipped example — render_constitution(load_profile()) returns a non-empty str with no error and no unresolved real placeholder (no {{ athlete/thresholds/zones/nutrition.* }}; the 3 escaped literal examples are allowed).
  • Live constants verbatim — 192 (max_hr), 177/192 (z5 bounds), 146 (easy_hr_cap), the derived 138 (easy_hr_cap - 8), 172 (cadence target), and a nutrition constant (1.8 protein / a carb multiplier).
  • StrictUndefined fails loud — an unfilled placeholder (e.g. a probe template {{ thresholds.does_not_exist }}, or a section missing an attribute) raises jinja2.UndefinedError — never a blank; _env.undefined is StrictUndefined.
  • Autoescape off — a prose substring with special chars ("180−age", "≤", "Z1–Z2") appears unescaped.
  • Fresh each call — two renders with two Profiles differing only in thresholds.max_hr produce outputs differing in that value (no stale memoized result).
